# 我的本地 AI · my-local-ai

> 中文 · [English](README.en.md)

> 你和你的本地 AI 伙伴一起，在一次次沟通里把它磨合得越来越顺手。

你出主意、提要求、指出哪里不对；它接住需求、记住你的口径、把纠正过的地方记下来。这个插件提供的是一套本地记录和相处规矩：记什么、怎么记、哪些线不能碰。所有记录都是你本机上的纯文本，换一个 AI、换一台机器，拷过去就能接着配合。

## AI 伙伴能做什么

装上之后，这个 AI 伙伴在这些方面有明确的功能：

- **记得住你**：记住你的偏好、长期关注、取舍倾向、表达节奏和雷区，跨会话不用重新交代；拿不准的推测会标可信度，先问你而不是替你拍板。
- **接得上上次，跨端也认人**：伙伴身份跟着名字走，不锁在某一个工具里——豆包、WorkBuddy、dsh 等装好插件的端都能认。开头报出伙伴名字，AI 就触发这套插件：按档案里预设的称呼回应你，调出这个伙伴的专属记忆和技能；通用理解所有端共读，专属记忆不串到别家。
- **可以由你定制**：伙伴的名字、称呼、方向标签、专属记忆和专属技能草案都能自己定；也可以按方向拆成多个伙伴，各记各的，通用理解共享。
- **会复盘自己**：遇到同类事先翻以前的判断；被你纠正后，记下原来的打算、偏差在哪、以后怎么改，下次少犯同一个毛病。
- **有交代**：信息不够先指出来，不凭空下结论。
- **会对照外部经验**：要挑方案、进陌生领域、或下“一般都这么做”这类判断时，先看看别人怎么解、踩过什么坑，再回头对照自己的前提。
- **收尾两件事**：「本轮小结」把这轮凭什么这么判断摆上台面，只写真正影响判断的来源和影响在哪；「想对你说」是私人话口，长短、语气、形式、内容不限，想说什么就说什么，也可以不说。两条都不写回库。
- **带得走**：全部记录是本地纯文本，换机、换 AI 时一起拷走，不锁在某个工具里。
- **知道边界**：库里的结论只是参考，前提不符就不照套；确实超出能力的事，会明说需要人工或换工具，不硬撑。

## 三个核心目的

这个插件不为"让 AI 更聪明"，只为三件具体的事。按重要性排：

**一、降低你和 AI 沟通的情绪成本。** 不用每轮重新介绍自己、重新解释偏好、重新纠正同一个毛病；不用猜 AI 在干什么；纠错说一遍就够，不必升级成拉扯。这一条最不依赖模型强弱——只要机制在，换个模型也一样省你话。

**二、减少 AI 对"临场推断"的依赖。** 把这个人的口径、已经确认的判断、踩过的坑写成文件，AI 需要时去读，而不是凭印象猜。跨会话、跨 Agent 都能接上。注意这里的分寸：库能省掉重复解释和重复犯错，但不能凭空给模型一项它没有的能力——真做不到的事，库里多写几行字也长不出来。

**三、让能力在反馈里慢慢长。** 经验主要从你指出问题、翻车、返工里长出来，而不是 AI 自己总结自己。每次偏差写进库，下一轮遇到同类情境能少犯一次；同一处偏差反复出现才收敛成稳定准则。这条目前还在补：缺"这条有没有被用上、用了之后还犯不犯"的证据，所以现在更接近积累，还不算增强。

## 谁会遇到这些问题

**一个人长期用一个 AI**：用得越久，越像每次重新认识——上次说过的偏好它不记得，踩过的坑还要再踩一遍，同一个毛病纠正三次还在犯；换了个对话窗口，前面的理解全归零。真正花掉你时间的不只是它答得慢，是你每次都得重新交代一遍。

**一个人跨平台用不同的 AI**：每个工具各有一套配置、各记各的，你在 A 端调教好的习惯到 B 端不生效；同一个项目在两三个 Agent 里轮流做，谁也不知道另一个已经试过什么、否掉了什么。

**两种情形共同的症状**：

- 偏好和口径存在脑子里，不在任何地方；
- 纠正完就过去了，教训没留下；
- 遇到没做过的事只在原有框架里打转，不主动去看别人怎么解；
- AI 做了什么、凭什么这么判断，你只能靠猜；
- 想换模型试试，等于从零开始。

插件就是把这几件事各给一个落点：偏好写档案、教训写纠错、外部经验登记索引、每轮收尾说清用了什么、所有文件都在本地纯文本，换工具直接拷走。

## 它接到任务会怎么做

先说大白话：它先掂量这事值不值得翻以前的记录；值得就翻，不值得就直接干；干完说一句这轮凭什么这么判断；有值得留的就记一笔。你说它错了，它先回想原本怎么想的，弄清错在哪一层，记下来，然后重做。

下面是展开，给你核对用，不是要它照表执行——顺序和投入多少，它自己按事情判断。

### 接到一个任务

1. **掂量要不要翻记录**。三个问题：这事以前干过没有、要不要拿主意、有没有值得留下的。都不沾就直接答，不翻也不写。
2. **要翻就先认伙伴**。你报了名字就按名字查名册，没报就看本端默认是谁；认到以后按档案里的称呼回应，再翻这个伙伴的判断记录。找到同类就看那一条，不整本读。
3. **掂量要不要去外面问**。要挑方案、进没做过的领域、要说"一般都这么做"这类话，或者你刚说它做得不对——那就去看看别人怎么做、踩过什么坑，回来对照自己原来的想法，别只改措辞。
4. **干活**。以前记下的结论只是参考，情况不一样就不照套。
5. **收尾说一句**。这轮凭什么这么判断的，只写真正用上的那点东西；「想对你说」想说什么都行，不限形式。
6. **记一笔**。值得留下的判断写下来；对你有新认识就更新你的画像；外面看到的记个来源；确实没什么可留，就不写。

### 你说它做错了的时候

1. **先回想**：它原本打算怎么做，别上来就改稿。
2. **弄清错在哪一层**：偏了方向、太粗或太细、顺序不对、做多了或漏了，还是依据本身就错了。分层不同，改法也不同。
3. **记下来**：原本想怎么做、错在哪、以后怎么改、什么情况下该想起这条、什么表现说明又犯了。
4. **分清是手滑还是想错**：环境、依赖、操作出了问题，还是方案本身有漏洞。
5. **改旧记录**：把相关记录改掉或降级，免得下次照错的来。
6. **重做**，并说清改了什么、为什么这么改，而不是默默换一版。
7. **同一个毛病第二次犯**，记一笔"又犯了"。这是它真的在进步的唯一硬证据。

事情小、错得明白时，走两条就够，不必把这几步演全。写下去的唯一理由是：下一轮真的能读到它。
## 功能逐项说明

每一项都按三句话写：**是干什么的**、**AI 怎么用它**、**它写回什么**。

### 1. 常驻说明：`rules/AGENTS.md`（各端派生出副本）

- **干什么**：讲清插件是什么、库里有什么、可以怎么用，再加 8 条"用了就得守"的规则。不是流程，没有"第几步"。
- **AI 怎么用**：每轮默认在上下文里，作为身份认知和行为边界。
- **写回什么**：不写回；它是规则源。改规则改母本，再跑安装脚本同步到各端。

### 2. 对用户的理解：`shared/user-profile.md`

- **干什么**：记这个人的思维方式、长期关注、取舍倾向、表达节奏、情绪雷区，供所有伙伴、所有端共读。
- **AI 怎么用**：开场或需要判断"他到底要什么"时读；每条分【明说】和【观察推测】，推测带可信度，拿不准就问本人。
- **写回什么**：观察到新特征就增量补一条；旧说法被推翻就改掉，不留两份打架的。

### 3. 沟通建议：`shared/communication-guide.md`

- **干什么**：把上一条的理解翻译成下一轮 AI 能直接照做的建议——称呼、语气详略、怎么解释和类比、主动做什么、避免什么、何时追问。
- **AI 怎么用**：决定回复的姿态和颗粒度时读，尤其是换了新 Agent、第一次接手这个人的时候。
- **写回什么**：发现更顺的沟通方式、或者某种说法踩到雷区，就更新；过时的直接改。

### 4. 伙伴身份：`companions/<名字>/profile.md` + 名册 + 活跃指针

- **干什么**：让伙伴跨端被认出来，身份跟着名字走。名册记所有伙伴的名字、称呼、方向标签、状态；`active/<端id>.md` 只记这个端此刻默认是谁。
- **AI 怎么用**：开场先认伙伴——读本端指针；你点名就按名字查名册。认到以后按档案里预设的称呼回应你，调出这个伙伴的专属记忆和技能，本轮内保持身份。
- **写回什么**：名字、称呼、方向变了就回写档案；切换伙伴只改本端指针，不动别的端。

### 5. 伙伴专属记忆：`companions/<名字>/memory.md`

- **干什么**：记这个伙伴亲历的东西——时间线、答应过还没办的事、收到的专属反馈、本方向的翻车。
- **AI 怎么用**：本方向任务优先读；别的伙伴目录只在事情本质明显匹配时才读。
- **写回什么**：追加式，带日期和来源端，不整份覆写别家档案；通用理解放共享层，不在各伙伴档案里抄一遍。

### 6. 能力索引：`methods/index.md`

- **干什么**：库里所有判断的一行目录——触发情境 → 准则一句话 → 可信度 → 条目链接。
- **AI 怎么用**：拿不准、或这类事以前做过时，先扫索引行，命中再读那一份，不整库读。
- **写回什么**：新增条目就加一行；某条被复用或被推翻，在行上标出来。

### 7. 能力条目：`methods/` 下的条目文件

- **干什么**：把一次教训写成能换任务复用的判断——触发情境（什么信号该召回）、准则（以后怎么判断）、反例（什么表现说明又犯了）、来源（哪次反馈长出来的）。
- **AI 怎么用**：命中索引后读这一份，用它的准则校正当前判断；前提不符就不照套。
- **写回什么**：验证通过提高可信度，翻车或前提不成立就修订降级；同类并入既有条目，不平行新开。

### 8. 稳定准则：`methods/patterns.md`

- **干什么**：同一类缺口反复出现时，收敛成更抽象的判断套路，并留 3–5 句"长期稳定模式"摘要，开场先带摘要再看条目。
- **AI 怎么用**：跨方向、跨任务时优先看这一层，减少逐条翻找。
- **写回什么**：反复验证的模式才加；单次任务不往这里塞。

### 9. 反馈盲点：`corrections/`

- **干什么**：用户指出问题时的记录——原来的打算、偏差落在哪（方向/粒度/顺序/范围/依据）、以后怎么改。
- **AI 怎么用**：同类情境再出现时读，避免重犯；这也是"再犯就记一笔"的落点。
- **写回什么**：每次被纠正、返工、理解偏差都写一条；同一条被第二次纠正时补复发记录。

### 10. 认可口径：`style/`

- **干什么**：记你觉得顺、认可过的表达方式，让后续 AI 不必重新试。
- **AI 怎么用**：决定措辞、详略、收尾方式时读。
- **写回什么**：一句"这样好"就够写一条；发现更好的说法就替换旧条目。

### 11. 外部来源与提炼笔记：`shared/index.md` + `shared/notes/`

- **干什么**：登记外部资料（链接 + 一句话价值 + 可信度），并把读到的思路提炼成短笔记；不存原文。
- **AI 怎么用**：要选型、进陌生领域、或要下"通常这么做"这类断言时，先看这里有没有现成结论，再去查；查完把来源登记回来。
- **写回什么**：一行来源记录；有价值的思路写成简短笔记，标"未在本机验证"。

### 12. 退役与遗忘：`methods/archive/`

- **干什么**：库默认只增不减，久了检索精度会掉、旧结论会被当成当前结论召回。
- **AI 怎么用**：清点时把前提失效、已被覆盖、长期零召回的条目移进来；反例类条目必须标清"这是反例，不是做法"。
- **写回什么**：归档动作本身留一行记录；翻车原因保留，不随退役删除。

### 13. Skill 手册：`skill/my-local-ai/` + `references/`

- **干什么**：库结构、条目写法、偏差分类、多伙伴机制、几种用法的展开。细则都在这儿。
- **AI 怎么用**：需要写条目、分偏差、查名册字段时按需加载对应一份，不整份读进上下文。
- **写回什么**：不写回；它是参照手册，不是记录。

### 14. 安装器与多端分发

- **干什么**：把 Skill 装进共享技能根和各 Agent 自己的技能目录，把规则写进各端的规则文件，把双库骨架落到主目录下。
- **AI 怎么用**：不参与；由你来跑。
- **写回什么**：规则文件里写带标记的区块（先备份原文件），可重复执行不重复写入；双库只补缺失文件，不清空已有沉淀。

### 15. 隐私边界

- **干什么**：库里只存配合任务需要的偏好、思路和沟通建议，不记你是谁。
- **AI 怎么用**：写任何档案、记忆、条目时都要过这一关；对话里出现的个人隐私，不写进库也不回填。
- **写回什么**：无——这条管的是不写什么。

## 快速开始

> **形态**：纯 Markdown + JSON 清单 · 无数据库、无后端、无运行时依赖 · 覆盖 18 类 Agent · 主目录相对，整机可迁移

### 安装

Windows：

```
cd 解压目录
pwsh -File install.ps1
```

macOS / Linux：

```
cd 解压目录
bash install.sh
```

脚本会：

1. 把 Skill 装进共享根 `~/.agents/skills/`，并复制到所有检测到的 Agent 自己的技能目录；
2. 把全局规则写入对应 Agent 的规则文件（已存在先备份为 `*.bak-my-local-ai`，再追加带标记区块，可重复执行不重复写入）；
3. 把双库骨架落到 `~/.my-local-ai/agent-library/`、`~/.my-local-ai/methodology-library/`（只补缺失文件，不清空已有沉淀）。

### 豆包工作桌面版（不走脚本）

> 「豆包工作桌面版」是 Doubao 客户端，与 dsh（DeepSeek Harness，本地配置目录 `~/.dsh`）不是同一个；dsh 走本地 `AGENTS.md` 槽位，由脚本写入。

豆包全局偏好存在账号配置里，脚本管不到，需手动贴一次：

1. 打开 **设置 → 工作模式设置 → 个性化 → 工作任务偏好指令**；
2. 打开 `rules/doubao-preference.md`，把分隔线以内的正文整段复制进去；
3. 保存即可，之后每个新工作任务默认携带这套偏好。

## 安装后第一步：建档

插件装好后档案为空，花几分钟填一次；之后 AI 会在对话里增量补充。文件在 `~/.my-local-ai/agent-library/`（Windows 即 `C:\Users\<用户名>\.my-local-ai\agent-library\`）：

### 第 1 步：起名字、定称呼 —— `companions/<伙伴名>/profile.md`

| 字段 | 填什么 |
| --- | --- |
| 伙伴名字 | 自己起一个；名册 `companions/index.md` 一行登记方向标签和检索偏好 |
| 称呼 | AI 怎么称呼你，你怎么称呼 AI |
| 方向标签 | 查库时优先召回哪些方向；其他方向条目只在任务本质匹配时读 |

> 多伙伴身份不靠每轮重新认识：身份按名字存档、跨端可认；每个端在 `companions/active/<端id>.md` 记本端默认伙伴，开场先读指针，你点名就按名字查名册；切换时只回写本端指针。技能池所有伙伴共享，不设访问锁。

### 第 2 步：记下怎么更好配合 —— `shared/user-profile.md`

只记有助于沟通与合作的理解，不记身份信息。每条区分【明说】（直接讲过）和【观察推测】（AI 推断），推测标可信度，拿不准先问：思维方式、长期关注与目标、价值观与取舍、表达方式与节奏、情绪倾向与雷区。

### 第 3 步：写给后续 AI 的配合建议 —— `shared/communication-guide.md`

基于上一份档案整理成下一轮 AI、其他 Agent 能直接照做的建议：称呼、语气详略、解释类比、主动做什么、避免什么、何时追问；最后写一两句话的"一句话画像"。

> 不想一次填完也没关系：先写名字和称呼，相处中 AI 会把新理解增量补进后两份；过时信息直接改，不堆旧记录。

## 路径约定（可移植）

`~` = 用户主目录（Windows `%USERPROFILE%`，macOS/Linux `$HOME`），不绑定具体机器：

- 资料库：`~/.my-local-ai/agent-library/`
  - `shared/user-profile.md` 对这个人的理解（所有伙伴共读）
  - `shared/communication-guide.md` 给后续 AI 的沟通建议
  - `shared/index.md` 外部来源登记；`shared/notes/` 提炼笔记
  - `companions/index.md` 伙伴名册（方向标签、检索偏好、状态）
  - `companions/active/<端id>.md` 本端活跃伙伴指针（按端隔离）
  - `companions/<伙伴名>/profile.md`、`memory.md` 身份与专属记忆
- 方法论库：`~/.my-local-ai/methodology-library/`
  - `methods/index.md` 能力索引（触发情境 → 准则 → 可信度）
  - `methods/patterns.md` 稳定判断套路
  - `corrections/` 反馈盲点；`style/` 认可口径；`methods/archive/` 退役条目
  - `companions/<伙伴名>/` 方向专属方法、纠错与技能草案
- 共享技能根：`~/.agents/skills/my-local-ai/`（所有伙伴可加载）

## 怎么看出它生效了

| 功能 | 看什么地方 |
| --- | --- |
| 少重复解释 | `shared/user-profile.md`、`communication-guide.md` 里逐条出现你的偏好和沟通方式，新会话开场就能读到 |
| 少重复纠正 | `corrections/` 里每条都有"原计划 + 偏差 + 以后怎么改"；同一偏差被记第二次时带复发标记 |
| 库真的被用上 | 收尾「本轮小结」只写这轮真正影响判断的来源和影响在哪；看完没改判断的不出现 |
| 外部对照发生 | 选型、陌生领域、要下"通常做法"这类断言时，回复里说明是否查了外部、查了哪类；`shared/index.md` 能看到新增来源行 |
| 判断在积累 | `methods/index.md` 出现新的触发情境 → 准则行；反复验证的进 `methods/patterns.md` |
| 身份连续 | 点名即按名册认出同一伙伴，按预设称呼回应并调出其记忆与技能；本端默认指针切换不影响他端档案 |
| 库没烂掉 | `methods/archive/` 里能看到退役条目；反例条目标了"这是反例" |

> 插件不规定流程。简单问答不必翻库、不必走总结格式，这属于正常用法，不是功能失效。

## 同步与迁移

- 规则母本是 `rules/AGENTS.md`；改完重新运行安装脚本即可同步到各 Agent 规则文件。
- 换机：整个插件目录 + `~/.my-local-ai/agent-library/` + `~/.my-local-ai/methodology-library/` 一起拷走，重新跑一次安装脚本。
- 新增 Agent：在 `manifest.json` 和 `install.sh` 的映射数组里各加一条（技能目录 + 规则落点）。
- 版本按小版本迭代：`0.1` → `0.2` → ……，规则映射或文档结构有改动时递增一位小版本号。
