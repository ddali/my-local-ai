# 多伙伴机制

## 名册：`companions/index.md`

每个伙伴一行：名字（对话里的称呼）；建档时间（YYYY-MM-DD，此前的交互不算它的记忆）；状态（活跃 / 待启用 / 休眠，待启用与休眠的不主动召回）；主适配方向标签（检索过滤用的关键词，通用条目不受限）；检索偏好；档案链接；备注。方向标签没定之前，新伙伴只按通用条目工作。

## 活跃指针：按端隔离

文件 `companions/active/<端id>.md`，`<端id>` 取清单里的 Agent id（dsh、workbuddy、claude-code …）。内容记当前伙伴、更新时间、切换原因（默认主伙伴 / 用户点名 / 方向匹配）。

身份不绑端：伙伴档案按名字存放，任何装好插件的端都能按名字认出同一个伙伴；点名触发后按 profile 里预设的称呼回应用户，加载该伙伴的专属记忆与技能。指针只记录本端默认伙伴，不决定身份归属——名册和档案才是身份的落点。

约定：

- 指针存在且指向在册活跃伙伴，就以它为当前伙伴，本轮内保持身份，不重复报名字；
- 指针缺失、损坏或指向不存在的伙伴，回退名册默认主伙伴并补一份指针；名册也没有默认时，先问用户定首位；
- 用户点名别的伙伴，或事情本质属于另一方向，读那份档案，**只回写本端指针**，不动其他端；
- 同端多会话同时切换可能互相覆盖，冲突时以最近一次用户明确点名为准，不替用户猜。

## 检索优先级

- 共享层随时可读：`shared/` 三份（用户理解、沟通建议、索引）、通用条目、共享技能池。
- 本方向优先：按当前伙伴方向标签，先看它的 `memory.md`、`notes/`、方法论库里的方向专属条目。
- 他方向按需读：别的伙伴目录里的条目，事情本质明显匹配其方向时才读，读完不混写进本伙伴档案。
- 技能不设方向锁：`~/.agents/skills/` 下谁都能加载，方向标签只影响召回排序。

## 记忆分层

| 层 | 位置 | 写入约束 |
| --- | --- | --- |
| 共享层 | `agent-library/shared/`、方法论库的 `methods/`、`patterns.md`、`corrections/`、`style/` | 写通用结论；一条一段，过时直接改 |
| 伙伴专属层 | `companions/<名字>/`、方法论库 `companions/<名字>/` | 追加式：带日期和来源端；不整份覆写别家目录 |

专属层只记本伙伴亲历的：时间线、承诺与未办结、专属反馈、本方向翻车与沉淀。对这个用户的通用理解放共享层，不在各伙伴档案里重复抄。各端只回写自己的指针。

## 新伙伴入场

读名册确认自己的状态、方向标签、检索偏好；读共享层；浏览共享技能池按需加载；专属目录空着是正常的，不继承其他伙伴的经历、承诺和纠错。沿用旧伙伴留下的二手结论时，保留原可信度标注，待验证的仍需本机实测。方向、口吻边界没定的，在 profile 标「待定」并主动问用户。

## 技能成熟度（参照，不是必经）

一行映射（索引里记场景 + 做法 + 结果 + 可信度）→ 方法条目（复用两次以上或翻车有原因才展开）→ 技能草案（放 `companions/<名字>/drafts/`，写明待回测项）→ 正式技能（对比或回测后进共享池）。草案不自动生效，回测要给对比基线或可复现步骤，不凭单次尝试升档。

## 冲突

- 方向未定：只做通用辅助，不硬认领跨界专题。
- 两边都沾：以事情本质为主；本端身份不变，必要时说明可以切到另一伙伴。
- 档案互相矛盾：共享层优先于专属层；同层看更新时间和可信度，拿不准标「待确认」并问用户。
- 不替伙伴编造经历：专属记忆里没有的历史不补写，需要时从共享层索引核对。
