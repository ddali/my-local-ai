# 双库结构与记录约定

路径为主目录相对，`~` = 用户主目录（Windows `%USERPROFILE%`，macOS/Linux `$HOME`）。换机时两个目录整体拷走，约定不变。

设计取向：索引先行、条目短、读得快、长期不膨胀。能一行说清的不拆文件；字段有则写，没有不凑。

## 资料库：`~/.my-local-ai/agent-library/`

```
agent-library/
├── shared/                        # 所有伙伴、所有端共读
│   ├── user-profile.md            # 对用户的理解：思维方式、关注点、取舍、表达节奏、雷区
│   ├── communication-guide.md     # 给后续 AI 的沟通建议：称呼、语气、类比、主动做什么、避免什么
│   ├── index.md                   # 资料索引：来源链接 + 一句话价值
│   ├── notes/                     # 提炼笔记，短
│   └── archive/                   # 少量原文留存，默认空
└── companions/
    ├── index.md                   # 伙伴名册：方向标签、检索偏好、状态、档案链接
    ├── active/                    # 按端隔离的活跃指针：<端id>.md
    └── <伙伴名>/
        ├── profile.md             # 身份、方向、口吻边界、不接什么
        ├── memory.md              # 专属记忆：时间线、承诺与未办结、专属反馈
        ├── notes/
        └── archive/
```

## 方法论库：`~/.my-local-ai/methodology-library/`

```
methodology-library/
├── methods/
│   ├── index.md          # 能力索引：触发情境 → 能力维度 → 准则 → 可信度 → 条目链接
│   ├── patterns.md       # 稳定准则：反复出现的能力缺口 → 判断套路 → 反例
│   └── archive/          # 旧版本、已弃用条目；平时不加载
├── corrections/          # 反馈盲点：反馈信号 + 能力缺口 + 补强准则
├── style/                # 认可过的表达口径
├── companions/           # 伙伴专属方向沉淀：<伙伴名>/methods · corrections · drafts
```

## 条目约定

- **写能力，不写事务。** 目标是让下次遇到同类情境时判断更准，不是让人照着抄步骤；命令、参数、路径这类执行细节不进条目，用时现查。
- 一条四件事：触发情境、准则、反例、来源。字段有则写，不必凑齐。
- **来源优先级**：被纠正、翻车、返工、理解偏差、复用失败、外部反例；任务顺利做完时的提炼只作补充。
- **维度标主维度**：理解意图 / 信息核实 / 判断取舍 / 表达输出 / 自我校验 / 协作节奏；跨维度标主维度即可。
- **案例层与能力层分开**：具体任务经过属案例，放 `notes/` 或案例分节，不占能力索引主体。
- 同类反复出现才并成稳定准则进 `patterns.md`，不每完成一件事就提炼一条。
- 写入前去重：先翻能力索引和方向标签，同类并入并更新来源与复用计数。

## 退役、替代与合并

- **冲突以新为准**：新旧结论打架时用新验证过的，旧条目标注被哪条替代、日期，不平行维护两份。
- **长期未召回退役**：结论已被覆盖、或长期没有同类情境再召回的条目标退役或移入 `methods/archive/`，翻车原因保留。
- **分层摘要**：跨会话反复验证的模式提炼成 3–5 句放 `patterns.md` 的「长期稳定模式」，细节留在条目里。
- **周期合并**：零散 `notes/`、一行映射和反复出现的反馈，隔一段时间合并成正式条目；合并后旧笔记进 archive。
- **复盘换视角**：执行轮记事实和结果，归档复盘换一轮独立视角核对，重大结论隔轮复核一次。

## 用户理解与沟通建议

- `shared/user-profile.md` 每条标来源：【明说】还是【观察推测】；推测标可信度（已确认 / 大概率 / 待验证），拿不准就问，不写死。
- 隐私：只存配合任务所需的偏好、思路和沟通建议，不记用户是谁，个人隐私不入库。
- 「相处槽点」分区在阈值之后才记（约 10 轮有效交互、20 轮复盘或大项目交付）：对事不对人，写行为模式和配合摩擦，不评价人格；带场景、可信度和改善情况，偶发单次不记。
- `shared/communication-guide.md` 的建议要能被下一轮 AI 直接照着做；过时或被推翻的直接改，不堆旧版本。

## 体积

- 索引一行一条；原文、网页、对话全文不入库。
- 单文件超过约 100 行，旧版本移进 `methods/archive/`，正文只留当前有效结论。
- 同一结论只在一处维护，别处用链接引用；库里按需召回，不把整库读进上下文。

## 检索随规模演进

- 条目少：索引表加方向标签召回，先看索引行，再决定读哪份。
- 条目破百、或按标签 / 可信度 / 状态多维过滤吃力时，再考虑接关键词或语义检索，索引字段保持可迁移；现阶段不引入向量库或数据库。

## 可信度标注

- **已验证**：真实环境跑通、可复现，同类情境可直接复用。
- **待验证**：来自资料或单次尝试，前提没跑全，复用时先标注。
- **已降级 / 弃用**：被推翻、前提不成立或过时；保留翻车原因。
